# Changelog

What changed in each release of BeamNG.Earth, newest first.

Fork entries separate **Изменения upstream** from **Наши правки**. Cache and validation notes follow separately. Mention unresolved errors only when the release changes their behaviour or adds relevant diagnostics; do not repeat unrelated known-issue disclaimers.

## 1.9.1-beta.51 — upstream dev bb65fafb (2026-11-14)

### Изменения upstream

#### Планирование дорог и загрузка

- По умолчанию загрузка дорожных тайлов больше не ждёт завершения чтения лидара: сначала доступны планы по имеющимся данным, затем они уточняются после прихода лидара. `BNE_LIDAR_PREFETCH=off` возвращает прежнее ожидание. Это сокращает критический путь загрузки, но не гарантирует окончательную геометрию до получения всех данных.
- Фоновая очередь уточняет незавершённые тайлы и планы только когда есть свободный дорожный процесс и не строится первый блок мира. Устаревшая работа дальше 6 км от игрока отбрасывается; очередь ограничена, неполные результаты повторяются с задержкой и ограничением попыток. `BNGE_LATE=off` отключает, `BNGE_LATE_PROCS` задаёт число фоновых процессов. Пользовательская отмена устаревших задач форка сохранена.
- Измерение дорог между стенами зданий перенесено в пакетные нативные проходы без удержания GIL, с параллельной обработкой. Подгонка нескольких мостовых настилов ячейки тоже выполняется параллельно; сами правила этих вычислений не меняются.
- Исправлены ступени у Kennedybruecke: вынос насыпи рельсов ограничивается дорогами у каждой собственной вершины, а дорога через открытый по данным высот участок тоннеля плавно сопрягается с ним. Исправления включены по умолчанию; `BNE_OPEN_TUNNEL_EASE=off` отключает последнее. Полнота результата зависит от исходной карты и высот.

#### Коллизии и terrain

- Дорожные коллизии перестраиваются по времени приближения машины и фактическим границам ожидающих объектов. Близкие обновления объединяются; при непосредственном приближении используется жёсткий приоритет. На высокой скорости уже готовые коллизии больше не ждут обычного таймера. `roads.reloadLog()` показывает причины перестроек. Улучшение кадровой плавности зависит от двигателя, машины и места; замеры upstream не являются замерами на компьютере пользователя.
- Terfast ускоряет три сканирования terrain при замене блока без изменения их результатов. В штатном запуске Windows включён по умолчанию; применяется только к распознанному поддерживаемому коду игры, иначе остаётся стандартный путь. `--no-gcpatch`, `BNGEARTH_TERFAST_OFF=1` или `BNGEARTH_TERFAST_WIN=0` отключают; `BNGEARTH_TERFAST_CHECK=1` включает сравнение со штатным результатом. Linux-компонент обновлён для сборки игры 2026-11-06; нужен соответствующий preload-компонент. Texkeep остаётся opt-in (`BNGEARTH_TEXKEEP=1`), его опасные пути ожидания переработаны; в этом выпуске он принудительно не включается.

#### Установка и размер загрузки

- Большинство текстур мода теперь распространяются как исходники без потерь, DDS вычисляются нативным модулем при установке и повторно используются по ключу. Игра по-прежнему получает DDS; исходники не кладутся в игровой мод. Первый запуск после обновления может тратить время на кодирование и требует места для готовых текстур.
- Общие белые и жёлтые дорожные знаки объединены в один атлас с отдельными ячейками различающихся знаков. BeamMP ZIP уже содержит готовые DDS, игроку не нужно кодировать его клиентский ZIP. Проверка ночных текстур учитывает генерацию при установке.

#### Подготовленные решения и инструменты размещения

- Добавлены подписанные архивы решений: планы дорог и факты ячеек, заранее рассчитанные доверенным строителем. По умолчанию выключены до включения `decisions.enabled` в CDN; `BNGE_DECISIONS=on` — явное включение. Подпись ed25519, версии данных, форматы и настройки проверяются до использования. При отсутствии, несовместимости, неверной подписи или сетевой ошибке расчёт выполняется локально. Для этого форка нужны архивы с его точным ключом форматов и настроек; наличие upstream-архива не гарантирует попадание в кэш.
- Запрос подготовки отсутствующего блока требует включённой статистики и отдельного разрешения `request` переключателя. Передаются номер области около 8 км и версия, без загрузки пользовательских расчётов; действуют ограничения частоты. Endpoint запросов в этом upstream ещё не развёрнут — работоспособность on-demand подготовки не обещается. `BNGE_DECISIONS_REQUEST_URL=off` запрещает запросы.
- Инструмент сборки BNWT умеет делить мир на смежные Hilbert-шарды и собирать индексы из их записей без хранения всех сотен гигабайт на одном CI-runner. STAC-индекс корректно скачивается для другого релиза данных. Добавлена документация самостоятельного размещения CDN/backend; наши приватные настройки и серверы в неё не переносятся.
- При сбое тестов последние строки логов теперь доступны непосредственно в CI, даже если артефакт логов скачать не удалось.

### Наши правки

- Сохранены российские знаки, профайлер, адресная отмена работ, векторный навигатор и необходимые локальные исправления геометрии. Российские цвета остаются отдельным атласом; его DDS также создаётся из исходника при установке. Общие знаки используют upstream-атлас.
- Добавлены проверки подписанных решений, фонового уточнения и terfast в основной набор и Windows CI. Новая упаковка объединена с документацией и файлами форка.

### Кэш, совместимость и проверки

- Нативный модуль 286 объединяет upstream 285 с ядрами форка; обе платформы пересобираются из общего исходника. Планы/факты — 66/27 вместо 65/27: старые дорожные планы больше не используются для изменённых правил. Архивы решений — формат 1; их ключ учитывает форматы, настройки и версии входных данных. Ручная очистка всего кэша не требуется.
- EXE и BeamMP ZIP следует брать из одного выпуска. Генерация DDS требует нового нативного модуля и совместимых исходников текстур. Подготовленные решения сокращают вычисления только при наличии точного совместимого архива, локальный компаньон остаётся необходимым.
- Проверки и сборка выполняются; непроверенные артефакты не публикуются. Проверки CI не заменяют длительный игровой сеанс, проверку поддерживаемой версии BeamNG и измерение скорости на компьютере пользователя.

## 1.9.1-beta.50 — upstream dev 1e7f73c7 (2026-11-13)

### Изменения upstream

#### Снимки местности и загрузка

- Добавлен источник `bngaer`: подготовленные аэрофотоснимки разрешения 1 м, AVIF 4:4:4 в пакетах BNGP масштабов 17–14. Источник выключен до включения в удалённом `cdn.json`; `BNGE_AERIAL=off/on` переопределяет переключатель. Нужна поддержка AVIF в Pillow и опубликованное покрытие. Пакеты имеют приоритет только там, где перечислены в файле покрытия; в остальных местах продолжают работать обычные источники. Отсутствующие пакеты не скачиваются вслепую.
- Исправлен выбор масштаба обычных снимков: источник без широтного ограничения снова используется крупнее его максимального масштаба с увеличением готовых тайлов. Это устраняет регрессию поздней загрузки снимков и земли. Ограничение `max_lat` теперь применяется только к источникам, для которых оно задано; подготовленные Sentinel-2 z14 за пределами покрытия используют более грубый масштаб.
- Добавлены атрибуция аэрофотопакетов и инструменты сборки/объединения пакетов, локального тестового сервера и фонового строителя. Новый строитель автоматически на нашем сервере не разворачивается. Полнота и разрешение зависят от открытых исходных снимков и опубликованных пакетов; замеры upstream не являются замерами на компьютере пользователя.

#### Запросы подготовки и приватность

- Подготовка отсутствующего пакета по запросу разрешена только при включённой пользователем анонимной статистике с учётом `BNE_TELEMETRY`. Запрос содержит номер посещаемой ячейки примерно 15 км, без идентификатора установки; это всё же приблизительное местоположение. Без известного согласия запрос не отправляется. Доступны отключение запросов через `request: false` в переключателе или `BNGE_AERIAL_REQUEST_URL=off`.
- Повторы ограничены одним запросом ячейки за шесть часов на машину и шестью запросами в час на процесс; сервис имеет собственные лимиты и очередь. Неуспех запроса не останавливает обычные снимки. Протокол и состав запроса описаны в TELEMETRY.md.

#### Проверки

- Upstream устранил недетерминированность тестовых BNWT-данных: seed теперь CRC32 вместо случайно солёного Python hash. Исправлены очистка memory-mapped файлов в тесте ширин дорог и ожидание фоновых записей обоих морских растров перед удалением временных каталогов.

### Наши правки

- Наши временные исправления двух Windows-тестов заменены upstream-реализациями. Сохранены необходимые локальные исправления, отмена устаревших работ, профайлер, российские знаки и векторный навигатор.
- Проверки аэрофотопакетов, переключателя CDN и морского кэша добавлены в основной набор; проверки новых снимков и CDN включены в Windows CI.

## 1.9.1-beta.49 — upstream dev b122aafc (2026-11-13)

### Изменения upstream

#### Повторные посещения и кэш

- По умолчанию готовые профилированные блоки земли сохраняются на диске: повторное посещение и перенос блока могут использовать готовые чанки из прежнего процесса или запуска. `BNGE_BLOCKCACHE=off` отключает; лимит папки следует общей ёмкости кэша (10%, в пределах 500–4000 МБ, 2000 МБ без заданной ёмкости), `BNGE_BLOCKCACHE_MB` позволяет задать его явно.
- Дальний план сохранённого места восстанавливается пакетно (`BNGE_FAR_RESTORE=off` отключает). Готовый базовый снимок блока сохраняется для следующего запуска, включая упакованную копию для игры. Сохраняются только окончательные результаты с полными входными данными; незавершённые или устаревшие результаты не становятся постоянным кэшем. Ускорение зависит от наличия подходящих готовых данных, это не ускорение любого первого посещения.
- Ошибки чтения учитываются отдельно для каждой сборки и передаются её дочерним задачам и потребителям общих результатов. Ошибка соседней сборки больше не отменяет сохранение исправного результата; ошибка из потока без известной области по-прежнему консервативно делает текущие результаты непригодными для кэша.
- Неполные планы помечаются между процессами, включая закреплённые наборы. Продукты, построенные без нужного лидара или батиметрии, остаются неполными при чтении. Версии еженедельных наборов входят в ключи с начала работы; сохранённые планы и тайлы после первого посещения могут находиться повторно.
- Декодированный DEM по умолчанию сжимается без потерь в f32z вместо большого `.npy`; `BNGE_DEM_MIRROR_ZSTD=0` возвращает memory-mapped `.npy`. Формат зеркала DEM — 4. Исходные измерения не меняются, старые производные файлы могут быть пересозданы автоматически.

#### Загрузка и возврат в мир

- Формы деревьев прошлого сеанса запоминаются и прогреваются под экраном загрузки. Новые формы загружаются по мере необходимости; проход заполнения ограничивает их число, а экран загрузки обрабатывает сообщения с бюджетом кадра. Это уменьшает задержки загрузки моделей, но не исключает все рывки движка.
- Повторный вход на уровень в том же запуске игры отправляет `world_reset`: серверные трекеры и удерживаемые коллизии/запомненные здания очищаются, чтобы дороги, здания и деревья не оставались невидимыми до телепорта.
- Батиметрия NOAA хранится на диске и запрашивается одним процессом/потоком за раз; морское дно блока подготавливается параллельно дорожным планам. Повышены отдельные лимиты параллельных фотозапросов к swisstopo и New York State; наличие данных и ограничения поставщиков сохраняются.

#### Необязательные подготовленные входные данные

- BNWT — побитно совместимые предварительно подготовленные входные слои Overture по ячейкам — выключены, пока не указан `BNGE_BNWT_URL` (HTTP(S), `file://` или папка). Формат BNWT 2: групповые чтения диапазонов, повторное использование пустого моря, индексы и части ограниченного размера. Можно подготовить слои воды/землепользования/инфраструктуры, дорог, зданий и мест. Это источник входных данных, не готовая геометрия мира и не отключение локального компаньона.
- Упомянутые upstream замеры ускорения относятся к его тестовым местам и состоянию кэша. В этом выпуске они не выдаются за результат измерений на компьютере пользователя.

### Наши правки

- В тесте морского растра добавлено ожидание фоновой записи перед очисткой временного кэша, устраняющее гонку удаления каталога на Windows. Поведение генератора не меняется.
- Исправлена очистка временного кэша в Windows-тесте ширин дорог: завершённые задачи и memory-mapped файлы освобождаются перед удалением каталога. Семантика передачи результатов и ошибок upstream сохранена.

- Сохранены адресная отмена устаревших работ, профайлер, векторный навигатор, российские знаки и необходимые исправления геометрии/отчётов. Передача областей ошибок объединена с существующим исполнителем задач; отмена проверяется отдельно.
- Добавлены новые проверки кэша блоков, базовых снимков, пакетного восстановления, BNWT, областей ошибок и возврата на уровень в основной набор и Windows CI.

Форматы планов/фактов остаются 65/27: итоговая геометрия не должна меняться из-за новых способов хранения. ## 1.9.1-beta.46 — upstream dev 96126efa (2026-11-13)

- **Lane counts through merges and splits**: where the map gives a lane count for some pieces of a motorway or

### Dirt roads and off-road ground
- **Dirt roads are worn now.** A gravel road used to follow the elevation data smoothed over 8 m, so it was as flat as
  a country lane and the only rough surfaces in the world were the main roads' own gentle undulation. A dirt road now
  has what a real one has: potholes (18-32 cm deep, 3-6 m wide), broken patches (a step of 12-22 cm with soft edges)
  and the odd deep pit (30-50 cm), over a soft rise and fall of ±15 cm. They are placed from the road's own position,
  so every process builds the same ones, and no step between two 2 m samples is steeper than 35 cm (56 cm on a
  `highway=track`), so a hole's far side is a slope, not a wall.
- **The main dirt roads stay much smoother**: a `motorway`..`tertiary` road mapped as gravel keeps a fifth of the
  damage of a country lane, and a forest `track` gets two and a half times as much: "on a forest road you cannot even
  get up to speed".
- **A dirt road leans to one side.** It also has a random cross slope, so now the left wheel is in a hole, now the
  right one, changing every 7 / 13 / 27 m, up to ±20 % (30-40 cm across a 3.5 m track). It fades out at the ends, so a
  junction joins level across.
- **Rougher land off the roads (optional, off for now)**: a soft, world-locked value noise at 9 / 4.5 / 2.4 m, about
  0.35 m standard deviation, wherever the ground is sampled. Turn it on with `BNE_TERRAIN_BUMPS=on`; it stays off by
  default until it is faster and kept out of towns, water and building sites.
- All of it is tunable: `BNE_DIRT_BUMP` (damage strength, 0 off), `BNE_DIRT_MAJOR` / `BNE_DIRT_TRACK` (the shares a
  main road and a track get), `BNE_DIRT_TRACK_WAVE` (how much of the soft undulation a track keeps), `BNE_DIRT_BANK`
  (the cross slope, 0 level), `BNE_DIRT_STEP` (the steepest step, m), `BNE_DIRT_SIGMA` (a minor dirt road's smoothing,
  m) and `BNE_TERRAIN_BUMP` (off-road roughness, m, with `BNE_TERRAIN_BUMPS=on`).

  rebuild. In testing at about 185 mph, collision was ready at least 480 m ahead of the car (before: as little as
  32 m).
- **Road surfaces should keep up better at high speed.** Above about 55 mph the world server builds the road tiles
  along your path, up to 14 seconds of driving ahead, in the order you will reach them. Things beside and behind you
  come later.
- **The ground under the car now comes first.** The terrain is built ahead of road tiles and far-away scenery when the
  server is busy.
- **Reduced the chance of falling off the edge of the loaded ground.** If the ground ahead is ever late (a slow first
  visit, a busy computer), the game now pauses at the edge with "Waiting for collision to load here" instead of letting
  the car drive off, and carries on by itself once it has loaded.

### Teleporting (drop the car at the camera)
- **Reduced the chance of falling through bridges and buildings after a teleport.** The pause now also waits for the
  bridges, tunnels, sidewalks and buildings around the car to have collision, then sets the car down on them.
- **Teleports to places that are already partly loaded pause too** if their bridges and buildings are not ready yet.
- **Dropping the car under a bridge** now lands it on the road below instead of on the bridge deck.

### Traffic and streets (thanks to hashk014, PR #35)
- **Roundabouts:** traffic now drives one way round in the right direction (the mapped one, else your country's
  driving side), cars on the roundabout have priority, and entries get give-way signs.
- **Traffic slows down for tight bends and hairpins**, braking in time, and follows speed limits that change partway
  along a road. Straight roads keep their posted limit.
- **Narrow old-town streets** between close buildings are drawn as narrow as 3 m wide with narrower sidewalks,
  instead of a wider default that ran into the buildings. Traffic takes narrow two-way streets more slowly.

### BeamNG.drive 0.40
- **Shingle roofs and runway markings should show their textures again.** 0.40 moved some of the game textures
  BeamNG.Earth uses.

### Installing from source (thanks to hashk014, PR #34)
- **Clearer help on Windows when a Python package cannot be installed.** With a Python too new for DuckDB's
  ready-made package, the installer now stops at once and explains how to use 64-bit Python 3.12 or the standalone
  .exe instead of failing after a long build and suggesting a network problem. Only affects installing from the source
  code; the .exe is unchanged.

### Other fixes

## 1.5.0 (2026-10-18)

The first release out of beta. Big themes: real bridges and tunnels, smoother driving, and credits for every data
source.

### Bridges
- **Real bridge types.** Truss, arch, suspension, cable-stayed and movable bridges are built with their real
  structure, from the US National Bridge Inventory (FHWA) and Wikidata (worldwide). Examples: the Queensboro, the
  Golden Gate, Sydney Harbour, the Rainbow Bridge, Tsing Ma, Tower Bridge.
- **Real heights and shapes.** Deck heights use the inventory's clearance over shipping channels. Decks no longer
  sag between supports. Anchor piers stand at the ends. Twin carriageways of one bridge sit at the same height.
  Double-deck bridges keep the right gap between decks.
- **Painted bridges** in their mapped colour (Golden Gate red, for example). Mapped towers and walkways are drawn as
  part of the bridge, not as buildings with windows.
- **Clearer roads on bridges.** Roads pass through bridge towers and gate buildings. Machine-detected "buildings" on
  bridges and on water (often barges or decks) are removed.
- Ramps start flush with their intersections.

### Tunnels
- **Mapped tunnels follow what's over them.** Depending on that, a tunnel becomes open road, a low stone arch or a
  full tube.
- **Inside.** Lamps on the walls and a darker inner wall.
- **At the mouths.** The portal faces reach the ground. Buildings over tunnels sit above the road. Dark gaps at
  arch mouths are fixed.
- Central Park's sunken roads and park bridges.
- Faster loading near long tunnels (for example the Gotthard).

### Streets and cities
- Street trees along sidewalks, medians on divided roads, and paved plazas and squares.
- Parking garages you can drive into, with ramps.
- Stoops and front steps start from the ground at the door.
- Buildings use their mapped wall material (stone, brick, glass).
- One broken white centre line outside the Americas.
- Props were mirrored (doors backwards on some walls); fixed.
- Rocks and plants sit on the graded ground beside roads.
- Italian orthophotos. Bare scree instead of false snow on mountain passes.

### Performance
- **Smaller hitch each time the terrain moves under you.** Each terrain block now loads only the ground materials it
  uses. In tests the stall dropped from about 300–440 ms to under 100 ms.
- **Buildings have a level of detail.** About a third of a mile away they switch to a simpler version: no window
  bays, roof clutter or steps.
- **What you're looking at loads first.** Road, tree and building tiles in front of the camera are built before
  the ones behind you.
- **Faster world building.** Road tiles build faster, and more of the server's terrain work runs in Rust.
- **Disk space fix.** The game's terrain texture cache no longer grows by about 550 MB a day; a session's entries
  are removed with it. Old entries from earlier versions stay in `temp/art/terrainmaterialcache` until you delete
  them.

### Gameplay
- **Dropping the car far away with the free camera is safe now.** The game pauses, with a banner saying it's waiting
  for collision to load, until the ground under the car has loaded. Then it resumes, instead of the car falling
  through the world.
- **At the edge of the loaded ground the game pauses instead of braking the car.** This happens when the server can't
  move the terrain (for example if it has stopped). It resumes once the ground follows; you can also resume yourself
  and drive back.
- **Credits show every data source** used around you: imagery, elevation, map data (OpenStreetMap, Overture,
  Microsoft, TomTom, and others), land cover, trees, sea depth, bridges, airports, gravity and weather. Each has a
  short name; the full wording stays on the settings page.
- The connection banner says whether the world server or a data provider is the problem.
- The launcher window is easier to read.
- The Windows .exe triggers fewer antivirus false positives.

### Known issues
- Bridges are much better but not perfect yet.
- Houses and buildings float above the ground in many parts of the world.
- High-speed driving still stutters while the world loads around you.
- A long session (about an hour of driving and teleporting) gets steadily more stuttery. Restarting the game
  clears it. The cause is being investigated (GPU memory fragmentation is the main suspect).
